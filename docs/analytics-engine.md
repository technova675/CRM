# Analytics Engine

Open **Intelligence → Analytics & Insights**. Explore dated paid media already saved in Performance, CRM leads and deals created, and daily Search Console snapshots already saved in SEO. Legacy AI Insights, Month comparison and saved browser views remain in their own tabs. The measured Explorer excludes the legacy relative weekly ad figures and campaign estimates.

**Data sources** supports Meta Ads, Google Ads, Google Analytics, Search Console, LinkedIn Ads, Ecommerce, Retail Media, Quick Commerce, Website Analytics and Programmatic. Use **Download CSV template**, select a client, and label the account/property and report. Supply one row per date and distinct combination of campaign, ad, creative, audience, geography and product. Use dimension columns consistently for a report. Empty measurements stay missing and a measured zero stays zero. Reimporting the same report replaces every row for dates supplied, preserving other dates. Use different report names for different breakdowns or methods. Each import supports up to 3,000 rows and 600 KB, with up to 80 feeds and 12,000 rows total, subject to the CRM library's 8 MB limit.

Explore by client, platform, campaign, ad, creative, audience, geography, product or date. Rows without the selected dimension are marked **Not reported**. Currency is reported as supplied, and paid media from Performance uses INR. Calculated metrics use sums from rows where both inputs are present. A missing metric or a zero denominator produces an unavailable value, with coverage visible. Use **Compare data feeds** to compare feeds separately. Cross-feed totals are deliberately avoided because revenue, clicks and conversions can overlap or have different definitions and currencies. CRM counts represent records created by date, and a lead is assigned to a client only through an unambiguous linked deal. Search Console uses site daily rows, excluding the query/page breakdowns.

## Optional live connector

The server accepts a trusted HTTPS read-only adapter at the exact URL in **ANALYTICS_CONNECTOR_URL**, with a bearer **ANALYTICS_CONNECTOR_TOKEN** and comma-separated Supabase user IDs in **ANALYTICS_CONNECTOR_OWNER_IDS**. The adapter must enforce provider access and tenant ownership of every account and report. Set those values on the server and restart. For Meta, Google Ads, GA4, LinkedIn, ecommerce, retail media, quick commerce and website analytics, the adapter must obtain the appropriate provider authorization and map the account's reports to this format. Native Search Console authorization remains in SEO.

The server sends only `ownerId`, `platform`, `account`, `report`, `start` and `end`. The adapter returns `{ "currency": "INR", "rows": [...] }` with up to 3,000 normalized records in the selected inclusive range (maximum 93 days). Row keys match the CSV template. Use JSON numbers for measured metrics and null or omission for unavailable metrics. Return a complete breakdown for every date included. Dates omitted by the connector are preserved in an existing report. Use a dedicated normalized report ID for each breakdown and ingest method. Provider account credentials stay at the adapter.

## AI Analytics Agent

Open **AI Insights**, choose a measured feed and metric, then select **Run AI investigation**. The agent compares adjacent windows of equal length. Leave the end date blank to use the most recent date in that feed. For a two-day CPA test, use adjacent dates with spend of 1,000 and 1,270 and 10 recorded conversions on each date. Choose **CPA** and **1 day** per window to see the measured 27% increase.

**Review measured evidence** runs the same comparisons without calling an AI provider. A headline comparison requires a measured value on each date and full row coverage in both windows. The AI uses computed aggregates and opaque evidence IDs. Raw rows, names, URLs, and CRM records stay in the app. Recommendations have priorities and experiments include a metric and decision rule. Missing data appears separately from AI hypotheses.

The CSV format accepts optional `placement` and `landingPage` breakdowns. Give a report with new dimension columns a distinct name. The Performance feed uses dated ad records and saved dimension mappings for segment evidence. Current budget and destination settings only provide context. Saved SEO observations do not establish that competition affected paid performance.
